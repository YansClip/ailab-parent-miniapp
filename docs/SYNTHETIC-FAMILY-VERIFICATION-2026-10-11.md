## 本机定向检查内容

- 两个虚构家庭只读到各自设备。
- 写入后另一连接池可以读取；更新设备名称不增加重复主键记录。
- 跨家庭访问、伪造身份/管理员角色、错误 AppID/身份来源被拒绝。
- 查看设备不等于允许定位和通话；客户端不能调用管理授权、绑定变更、维护接口。
- 撤回同意、停用成员、移除孩子关系、取消查看权限后，旧访问立即失效。
- 解绑后设备不再出现在可见列表；换绑后旧家庭不能继续访问，新家庭须使用新绑定版本。
- 事务失败后绑定记录恢复原样。
- 定向测试中设备服务调用次数为 0，无位置、音视频请求。
- 定向测试自行移除精确命名的本机测试记录，业务表回到空表。
- 最小权限本机账号无全局管理权限、无数据库级权限、无转授权权限。

## 为什么没有在云端网页做回滚验证

同一批 DMC SQL 中执行 `SET @qa_probe=...` 后，下一条 SELECT 读回 NULL。该页面不能据此保证跨语句使用同一个数据库会话，所以没有通过这个网页执行跨语句写入事务，也没有把它当作回滚证明。

本机通过真实连接池验证回滚与并发；云端仍需由服务端同一连接完成这两项验证。成功执行单条 `FOR UPDATE` 只证明这条查询有权限，不证明整个跨请求事务可靠。

未修改云端记录、权限、服务配置、数据库密码或主应用模式；设备 A 继续保持版本 3、仅可查看。

### 建议下一阶段范围（尚未执行，待用户确认）

目标是让手机通过云端读取人为生成的测试点，并能区分有效、过期和离线，而不是读取手机自身位置或真实儿童位置。

预期链路：电脑临时模拟设备上报 → 独立定位接收服务 → 现有私有 MySQL → 现有微信业务后台 → 小程序专用测试界面。

分两步推进：

1. 不增加云资源的准备阶段：补齐可重复的模拟发送工具、测试界面和部署/回退材料，保持现有已部署后台与测试设备权限不变，先做本机验证。
2. 云端部署阶段：独立接收服务、上传凭证、设备白名单及定位提供方配置均须明确；仅对虚构设备 A 开放本轮测试定位权限。新增资源的费用与实例策略需先核对并由用户确认，再执行部署。原微信业务服务和数据库不能为了上传而直接开放公网，通话继续关闭。

验收：新测试点可读、无定位或离线不保留旧点、点位过期自动失效、旧绑定/错误签名拒绝、撤回定位权限后不再读取位置。电脑在该阶段只临时产生测试报文；它不替代正式云端业务后台，也不能因此宣称真实 TCP 硬件入口已部署。

现有 `LOCATION_PROVIDER=disabled` 和缺少云端上传入口是进入手机模拟定位验收前的部署缺口，不应只把前端开关打开就报告完成。已核对的旧部署文档仅是历史记录，当前部署进展以本报告和本轮用户反馈为准。
