# 固定 17 字节定位联调 · 2026-10-08

## 本轮约定

用户确认保留开头注册 JSON，坐标改用固定长度明文。仅调整本机联调，不部署云端、不接通真实音视频、不自动开启公网。

连接内的数据顺序：

```text
{"imei":"TEST-DEVICE","csq":20}120.0001_30.00010120.0002_30.00020
```

上述注册标识和坐标都是合成示例。注册 JSON 是可选的，每次连接只允许在开头出现一次，必须为完整对象，并含 `imei` 或 `iccid` 字段；允许其他既有字段。不保存或以设备号码作为认证。JSON 不需要换行，长度上限 512 字节。

坐标格式严格为 `DDD.dddd_DD.ddddd`，共 17 个 ASCII 字节：经度 8 字节、下划线 1 字节、纬度 8 字节。当前约定只有正数，经度整数三位、纬度整数两位；小数末尾零不能删除。不支持 NMEA 度分、负号、科学计数法、GPS/END 前后缀或中间空格。这是本次样机联调协议，不是全球通用的正式定位协议。

不需要换行，也不发送 ACK。完整报文之间可兼容真正的 CR/LF，但不接受文字 `\\r\\n` 或 `0D 0A`。坐标系仍须单独确认；不因格式通过便假定 WGS84。

## 接收行为

- TCP 拆包：不足 17 字节先等；收齐才解析，不用静默时间猜结束。
- TCP 粘包：注册 JSON 按对象边界识别，后续每 17 字节拆成一条坐标。
- JSON 内部字符串、转义符和嵌套对象不会被错误的右括号截断。
- 坐标字段位置、小数位或范围错误：报错并断开，不扫描后面的数字猜测重同步。新的 TCP 连接重新从注册／坐标开头解析。
- 未完成 JSON 或坐标半包超过 15 秒：断开。90 秒无数据：清理连接。
- 固定长度协议依赖硬件遵守字节数，不能检测所有数据损坏：例如更长数字的前 17 字节恰好合法时，无法预知后续多出的数字。正式协议建议加入类型、长度、序号、采集时间、校验及设备鉴权。
- 坐标仅短期保留在内存，不保存位置历史；注册包和定位格式通过不等于身份认证或真实定位有效。

## 操作

默认后台启动已使用 `fixed17`。联调台 `http://127.0.0.1:18866/` 的连接地址下方应显示“固定 17 字节”。浏览器刷新即可获取新说明。

1. 本机自测选“注册 JSON + 坐标粘包”，应分别出现注册记录和 17 字节定位记录。
2. “字节不足”是故意失败测试，出现异常属预期；不要把自测计数当硬件接收证据。
3. 远程测试需用户在窗口开启公网，重新复制当前地址。只发合成坐标和测试标识；真实定位跨公网前必须补齐认证和传输保护。
4. 工程师建立 TCP 长连接，先发注册包，再每 10 秒发 17 字节坐标。至少观察 3 条持续上报，没有格式错误和反复重连。
5. 选对应连接、确认坐标系、生成配对码后，小程序开发者工具可读取该连接的位置。断开会清除坐标，新连接需重新选取配对。

命令行：

```sh
npm run device:tcp
npm run device:tcp:send -- --scenario registration
npm run device:tcp:send -- --scenario split
npm run device:tcp:send -- --scenario sticky
node --test tests/tcp-fixed17.test.js
```

若回到旧换行协议，接收端和发送端都显式指定 `--framing line`。请勿在常驻服务占用端口时重复启动。CLI 与独立穿透脚本默认 fixed17；底层 receiver 库默认 line 保留，以兼容旧测试调用。
