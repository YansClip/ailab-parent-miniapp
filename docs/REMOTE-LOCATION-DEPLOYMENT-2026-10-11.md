## 1. 要达到的效果

你的电脑关机后，工程师的硬件仍能把合成坐标发到云端；你与指定工程师用各自获授权的微信打开小程序，可以查询最新测试结果。

```text
异地硬件（发送合成坐标，协议不变）
    │ TCP
    ▼
新增常在线接收服务器（解包、限流、测试白名单）
    │ HTTPS＋后台签名
    ▼
新增云托管定位上传服务（验签，只处理上报）
    │ 内网
    ▼
现有私有 MySQL ← 现有 ailab-device-gateway（身份与家庭权限）
                                  ▲
                                  │ wx.cloud.callContainer
                        你／工程师的手机小程序
```

数据方向始终是**硬件上传，手机查询**；服务器向手机返回结果不等于手机反过来给硬件提供定位。服务器代替本机持续接收，并非让硬件直接连接小程序。

这里“随时看”指打开小程序后查询。手机熄屏、微信后台持续刷新或推送提醒，不在本轮范围。音视频也不在此定位预算和验收范围。

## 3. 旧协议兼容：部署前必须补的代码

现有 `server/mini-device-cloudrun/location-tcp-relay.js` 要求额外 AUTH 首包，非本机接入要求 TLS；它不是旧固件可直接接入的版本。**不能直接把这个程序部署后就让工程师改地址。**

下一实现阶段增加独立的“旧协议合成数据测试适配器”，不删除正式接收器的安全检查：

- 注册 JSON 仍用原 `imei` 或 `iccid` 字段；使用双方约定的虚构标识，不发真实 SIM／设备号。原本地解析器允许无注册，但云端测试为映射设备需首包注册；不增加 AUTH 首包。
- 坐标仍为 `DDD.dddd_DD.ddddd`，严格 17 个 ASCII 字节；没有 ACK，不能把十六进制展示文字当真实报文发出。
- 仅允许约定虚构设备与少量固定合成点；其他坐标拒绝且不写日志。设备号不是密码，不能把注册成功视为设备认证。
- 公网测试入口限来源 IP、连接数、报文长度、上报频率与测试时段；若工程师出口 IP 不稳定，先协商受控隧道或其他保护，不默认对任意来源永久开放。内网数据库暂不使用 TLS 的旧决定，不等于批准公网传输真实位置。
- 固定 17 字节没有 GPS 采集时间、定位有效标志或序号。因此只显示“测试坐标收到于某时”，不能声称“刚刚测得真实位置”。
- 收包时间保留为 `receivedAt/observedAt`，不填成 `measuredAt`。合成测试记录走隔离的数据类型／集合和显式测试查询，不混入正式 GNSS 有效位置。需补相应后端与手机测试展示；当前新增检查入口尚不提供这个旧协议测试点接口。
- 云间上报仍为 HTTPS 验证证书＋签名＋设备白名单。密钥仅在服务器与上传服务中，不给手机，也不发给硬件工程师。

现有正式存储在缺少采集时间时会返回 `capture-time-missing`、不显示有效点。这是保留的安全边界，不应通过伪造时间或把 `LOCATION_PROVIDER` 改成 `push` 来绕过。

正式接入真实人员定位前，另行确认设备认证、传输加密、时间／无定位表达、授权撤回与数据留存。现在不要求硬件擅自更改已确认的报文格式。

## 5. 费用确认后如何实施和验收

1. **先完成本地适配与回归**：用协议模拟器发送原字节，验证注册、拆／粘包、非法坐标、断线、重连、乱序风险、超时、跨设备与撤权。新适配器及测试查询未完成前不购买资源来空等。
2. **核对并确认账单方案**：检查实际套餐、云服务规格、原模板是否仍产生费用、免费额度；用户确认后才开通。不开自动续费，不顺带关停旧服务。
3. **部署独立上传服务**：建议服务名 `ailab-location-ingress`，仅验签上报，容器端口 8080，`SERVICE_ROLE=location-ingress`；使用私有数据库及受限应用账号。测试适配的数据契约也需在此部署，不能只上传目前的旧代码。
4. **部署 TCP 接收器**：建议独立测试端口 18765（采购后检查实际占用），进程自动重启。仅开放约定测试来源；SSH 限管理员来源、密钥登录。MySQL 3306 不对公网开放，数据库密码不放接收服务器。
5. **配置云间签名与隔离**：`LOCATION_RELAY_KEYS_JSON` 等私密配置只在服务端保存，凭证只准上报指定测试设备。云业务服务仍保持私有微信网关访问；绝不为了接硬件而开放其公网入口。
6. **仅授权测试身份**：核验你和工程师各自在此 AppID 下的真实微信身份，只关联虚构测试家庭／设备。权限变更前明确两人及设备范围；不发 root、数据库密码或云控制台管理权限给工程师。
7. **更新内部小程序版本**：上传可辨认的测试版本并设置体验版；不是提审或正式发布。提供状态、合成点收包时间、离线／过期清点和可控前台刷新；离页停止，不采集手机位置。
8. **双方验收**：硬件每 10 秒上报合成点；两部获授权手机前台均能查询到更新。关闭你的电脑后仍有效；停止硬件后按约定时效清点；撤销工程师权限后不可查询；其他微信号不能看到设备。保留脱敏证据，不把本机模拟器结果标为硬件证据。

首次验收目标：1 台测试设备、2 位指定测试者、连续 30 分钟，并追加一次电脑关机测试。原始协议不能证明定位采集新鲜度、GPS 精度或真实设备身份，验收只确认约定测试数据链路。

回退：关闭测试 TCP 端口并停上报程序，撤销测试签名与测试读取权限；需要回滚云代码时使用明确的前一版本。只清理本次标记的虚构记录，不删除数据库或原 Django 服务。先停止上报，再停止上传入口，避免无限重试。

## 6. 工程师如何使用小程序

两种权限不是一回事：[微信官方协作与发布文档](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/release.html)

- **仅用手机做联调**：推荐“体验成员＋体验版”。微信公众平台登录此小程序 → 成员管理 → 体验成员 → 添加其微信号 → 按页面提示完成管理员确认。开发者工具上传测试代码后，在版本管理中选开发版本并设为体验版，把对应体验版二维码单独给他。
- **需要用开发者工具开发／调试**：添加项目成员并授予开发者权限，再使用开发版／预览码。不要只为扫码测试就给完整管理员权限。

微信号用于添加成员；OpenID 用于我们后台识别当前小程序内的用户；AppID 标识小程序。三者不能混用。二维码不自动授予成员权限；成员权限也不自动授予数据库中测试设备的数据权限。

工程师首次打开后主动同意所需隐私说明，在体验设置获取本人身份。后续仅将其身份关联虚构测试设备，并做一次未授权／授权／撤权验证。不要复制你的 OpenID 让他冒用。

备案与内部测试成员是两个问题。当前已经能使用开发版，不代表一定能发布，也不能由此保证该账号未备案时所有体验版功能均可用。以微信后台实际允许的上传／设为体验版及其提示为准；若备案门槛拦截，先按官方流程完成备案，不用二维码分享绕开。正式开展业务前需履行备案要求。[主管部门说明](https://ynca.miit.gov.cn/zwgk/tzgg/art/2024/art_9a052419399c4efbbd43b87172e658b8.html)

本次浏览器工具对微信公众平台页面触发站点安全限制，不能代操作成员管理；不是已尝试添加成功。管理员需手工完成上述成员步骤。工程师微信号尚未提供，也尚未授予任何身份新权限。
