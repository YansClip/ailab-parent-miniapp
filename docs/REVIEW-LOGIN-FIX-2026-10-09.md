# 审核整改：先浏览，再主动登录

日期：2026-10-09。项目：`miniprogram-1`。AppID 保持 `wxc5abf3407ed4ef30`。

## 本次解决的问题

审核截图指出：用户尚未浏览服务即被要求授权登录。原启动流程依次进入欢迎、隐私和登录，四个主入口依赖登录与家庭设置，缺少独立的公开浏览路径。

改为默认打开首页。公开内容与私人数据分开，不用伪造登录状态或取消后台权限来开放浏览。

| 入口 | 不登录即可使用 | 仍需要主动登录与权限 |
| --- | --- | --- |
| 首页 | 阅读、展开公开好奇心卡片示例 | 本人孩子的推送、成果和待办 |
| 守护 | 展开位置、音视频及设备工具说明 | 查询绑定设备、刷新位置、发起通话及配置设备 |
| 成长 | 阅读简报示例、展开六维覆盖含义 | 本人孩子的探索记录、报告和成果 |
| 我的 | 查看公开指南、关于和协议 | 家庭、设备、消息和账号管理 |

公开示例明确标注示例，不读取缓存家庭，不含孩子标识，不触发位置、音视频或设备接口。六维仅解释相关内容的探索完成覆盖，不评价孩子能力。

## 登录与拒绝路径

1. 初次打开、旧欢迎页链接、退出登录，均可回到首页浏览。
2. 用户点击“登录并连接家庭”后，才进入隐私选择与登录。
3. “暂不同意，继续浏览”“暂不登录，继续浏览”返回所选主入口，不退出小程序、不自动再次弹出登录。
4. 未绑定的已登录用户仍可浏览；主动连接家庭时才进入设置。
5. 不强制手机号、头像、昵称。不增加获取这些信息的权限调用。
6. 跳过登录或离开页面后，迟到的微信回调不再写登录状态或跳转。
7. 私有 API 保留身份与权限校验；退出、撤回或未登录时主页面清空私人显示数据。

## 修改位置

- `app.json`：默认首页。
- `services/access.js`：公开浏览、自愿登录和返回目标白名单。
- `services/public-content.js`、`components/public-preview/`：独立公开内容与交互。
- 四个主页面：游客分支，不启动私有读取或设备轮询。
- 欢迎、隐私、登录、拒绝页：浏览返回与登录取消保护。
- 指南、关于：允许公开阅读；私有操作再主动登录。
- `tests/public-browsing.test.js`：新增 12 项针对性回归；已有测试适配新启动流程。

保留既有硬件联调与 UI 工作，不上传、不发布、不部署、不推送。
