## 已复现并修复的问题

| 优先级 | 问题与后果 | 修复与验证 |
| --- | --- | --- |
| P1 | 后台权限检查发生在数据库事务之前；请求排队时撤权或换绑，仍可能创建旧订阅、刷新任务、通话记录或设备占用 | 在同一事务中重新检查成员权限和绑定版本；覆盖 3 种操作 × 撤权/换绑，断言不产生记录或上游指令 |
| P1 | 仅设置 SQL 查询超时不能覆盖连接池排队、事务开始/提交/回滚等阶段；超时或回滚失败的连接可能被再次使用 | 显式管理连接生命周期，为各阶段增加截止时间；异常连接销毁，迟到获取的连接归还但不执行旧请求。真实 MySQL 锁等待测试确认超时后无迟到写入、连接池可恢复 |
| P2 | 体验设置页离开、身份状态变化时，旧异步结果仍可能回填；等待状态可能无法恢复 | 页面隐藏时清理结果并使旧请求失效；回包再次检查隐私同意及请求版本，避免旧数据回填或按钮卡住 |
| P2 | 模拟定位会话自然到期或在请求途中到期，页面可能仍保留配对/旧点状态，不能顺利重新配对 | 会话失效时清空坐标、计时器及旧请求标记，恢复配对入口；两种到期时序均有回归 |
| P2 | 本机网络异常如果 SDK 不回调，模拟配对或读取可能一直等待 | 加独立 5 秒截止时间并中止请求；迟到结果不能恢复过期会话 |
| P2 | 旧 TCP 台切到后台再返回，之前的状态请求可能恢复已经隐藏的报文原文 | 请求附页面版本，隐藏页面后旧结果失效；回归证明迟到回包不能恢复原文 |
| P2 | 旧 TCP 台失联后还保留“正常”的内存快照，切换选项可能显示旧在线状态；恢复后控件可能仍禁用 | 失联清空快照、原文、配对码和媒体状态，显示未知并禁用控制；恢复后重新启用适用入口 |
| P2 | 新模拟定位台重启后临时凭证改变，旧网页只有失败提示，缺少可理解的恢复入口 | 增加「重新连接工具」，清空旧位置/配对信息；实际停止、重启、点击恢复并重新配对成功 |
| P3 | 模拟定位每 250 毫秒重复刷新相同页面数据；README 仍混用历史页数和旧联调入口 | 只有点位有效状态或倒计时秒数改变才刷新；文档区分新模拟台、旧 TCP 台和现有云端链路 |

超时不等于写入必定失败，尤其提交阶段的结果可能不确定，因此没有加入自动重试写操作；仍应通过原操作编号查询最终结果。独立超时是每阶段上限，不是整个复杂业务请求的统一总耗时承诺。

## 未解决风险与发布前条件

### 1. 云端只读出现过一次短暂失败

健康检查成功后，第一次设备列表读取返回「私有数据库暂不可用」，人工重试后读到虚构设备 A，绑定版本为 3。**根因尚未确定**，不能仅据此归因于数据库自动暂停、连接池、密码或网络。

下一步需以该时段服务日志/数据库状态及请求耗时定位。当前工具无法直接检查云控制台页面，本轮未更改任何云配置或重启云服务。未经验证，不建议靠扩大实例、关安全设置或重复写入来绕过。

### 2. 未启用的云函数部署依赖存在告警

对现有锁文件执行生产依赖审计：

- 当前云托管运行依赖目录 `server/mini-device-cloudrun`：0 个已知告警；不等于保证不存在未知漏洞。
- 可选旧云函数目录 `cloudfunctions/miniDeviceGateway`：6 个受影响包（5 高、1 中），链路涉及 `wx-server-sdk`、CloudBase SDK、Axios、`lodash.set`/`lodash.unset`。这不是已经验证的 6 个可利用应用漏洞。
- 当前 Dockerfile 仅安装云托管目录依赖并复用 `lib/`、`providers/` 源码，没有安装这个旧云函数 SDK 依赖链。
- 未执行自动强制修复：包管理器给出的方案会把 SDK 大幅降级，不能用“审计数字清零”替代兼容性与功能验证。

当前保持旧云函数入口不部署；如确实要启用，需另做 SDK 升级/替换、依赖复核及契约测试。参考 [Axios 官方安全公告](https://github.com/axios/axios/security/advisories/GHSA-jr5f-v2jv-69x6)。数据库连接生命周期参考 [mysql2 官方连接池说明](https://sidorares.github.io/node-mysql2/docs/examples/connections/create-pool)。

### 3. 真实数据和规模化上线尚有前置条件

- 云端仍按此前决定仅做内网虚构测试；真实儿童位置进入前，要验证 TLS、设备身份认证、最小权限、审计、数据保留与删除、备份恢复。不能用本轮本机账号权限测试替代云端 `ailab_app` 的授权核验。
- 本轮未在云端 MySQL 5.7 上运行写入、事务或迁移测试，也没有备份恢复演练。
- 当前存储为 JSON 记录表、有限关系查询和全局事务互斥，适合小规模联调；大量设备时可能出现查询/锁瓶颈。上线前按目标量做索引、分页与压力测试，不应直接扩大到生产规模。
- 业务会话清理/撤权协调需要部署侧作业和供应商到期约束。源码提供的维护方法不等于定时任务已在云端启用；必须核验运行与失败告警。
- 本轮不是对所有页面、所有 iOS/Android 真机、弱网长跑的穷尽测试；未执行完整渗透测试。
- 实际 TCP 网关、设备签名与采集时间、坐标系、媒体服务、微信许可、设备固件兼容性均需单独联调；模拟通过不能替代硬件证据。
