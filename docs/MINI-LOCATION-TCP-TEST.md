## 1. 先看结论

本机接收程序已提供，支持硬件截图中的 **经度_纬度** 文本，不需要安装第三方 npm 包。

- 已做：TCP 接收、格式检查、拆包/粘包处理、无换行探测、接收状态展示、模拟发送、可选回包、可选口令与 TLS、自动测试；已补临时公网穿透及合成数据回传验证。
- 未做：真实硬件远程上传、小程序正式定位对接、云端部署，以及真实位置跨公网所需的设备端认证与加密。
- 不修改：小程序 AppID、演示开关、页面、CloudBase 设备适配器及音视频功能。
- 不保存：精确坐标文件、设备号码、位置轨迹。每条连接只在内存保留最近一条记录，60 秒后或断开时清除。
- 默认不打印坐标，也不回包。程序显示“收到完整坐标”仅表示格式通过，不表示位置有效或小程序已更新。

截图能确认：经度在前、纬度在后、以下划线分隔，连续记录约 10 秒一条。**这只是观察，不是已确认的固定协议。** 截图看不出结束符、坐标系、采集时间、身份认证和回包要求。

### 现在使用的临时公网入口

已增加 Pinggy 免费 TCP 穿透，只转发本机 18765 接收端口，不转发 Mac 远程登录、文件、其他服务或调试面板。无需注册账户、购买服务或安装第三方客户端，使用 Mac 自带 SSH。

- **启动**：双击 `tools/mini-location-tcp/启动远程测试.command`，确认只用合成数据后输入 YES。工具一起启动接收和穿透，打印域名、端口、自动关闭时间。
- **停止**：双击 `tools/mini-location-tcp/停止远程测试.command`，或在启动窗口 Ctrl+C。只停止本项目记录的进程，不批量结束其他 SSH/Node 进程。
- **有效时间**：工具最多 55 分钟自动关闭，不自动重连；服务商免费连接本身限 60 分钟。重启后地址变化，要重新发给工程师。
- **当前地址**：查看启动窗口或 Git 忽略的 `tools/mini-location-tcp/private/current-tunnel.json`。一次性地址不固定写入 PRD、固件或小程序配置。文件中 `ready-unverified` 只表示自动获得地址，实际接收结果看接收窗口。
- **认证隔离**：只生成本测试用途的 SSH 密钥，不使用个人 SSH agent，不改全局 SSH 配置；首次记录服务商主机密钥，后续拒绝其变化，不关闭主机校验。
- **数据边界**：只能用于合成坐标，不是具备设备认证与端到端加密的正式定位通道。该限制是使用约定，程序不能自动判断坐标是否属于真人。第三方节点可能位于境外，当前禁止上传儿童或个人真实位置。

命令行启动（先停止独立接收程序，避免端口冲突）：

```sh
npm run device:tcp:tunnel -- --synthetic-only
# 固件仍无换行时，只作候选探测：
npm run device:tcp:tunnel -- --synthetic-only --framing idle-probe
```

后续如需真实位置测试，必须先补设备身份认证及设备端到接收端的加密方案；仅 SSH 中转段加密不算端到端加密。当前不自动启用安全设置未确认的硬件连接。

来源：[Pinggy 官方 TCP 说明](https://pinggy.io/docs/tcp_tunnels/)、[免费时限及隐私说明](https://pinggy.io/help/)。

## 2. 你现在怎么操作

### 第一步：启动接收

在 Finder 中打开项目的 `tools/mini-location-tcp/` 文件夹，双击 **启动接收程序.command**。若系统不允许双击或找不到 Node.js，使用终端：

```sh
cd /Users/sc/WeChatProjects/miniprogram-1
npm run device:tcp
```

看到下列文字，表示本机正在等待连接：

```text
本机 TCP 接收地址：127.0.0.1:18765
等待设备…… 按 Ctrl+C 停止。
```

保留这个终端，不要关闭、休眠。`127.0.0.1` 是你的电脑自身，**不能把它当作公网地址发给异地工程师**。18765 是本程序的本地监听端口，不是截图连接列表里的设备来源端口。

### 第二步：用另一个终端模拟发送

```sh
cd /Users/sc/WeChatProjects/miniprogram-1
npm run device:tcp:send
```

接收窗口应显示两条“收到完整坐标，格式校验通过”。模拟器只向本机发送合成坐标，没有访问截图中的第三方服务。

需要人工核对数字时，先 Ctrl+C 停止旧程序，再显式开启显示：

```sh
npm run device:tcp -- --show-coordinates
```

开启后坐标会出现在终端滚动记录中，勿重定向成日志、录屏转发或使用真实儿童位置。默认隐藏模式适合日常排查。

### 第三步：工程师确认结束符前，测试无换行兼容

停止旧程序，运行：

```sh
npm run device:tcp:probe
```

另一个终端运行：

```sh
npm run device:tcp:send -- --scenario no-newline
```

约 1 秒无新字节后，会显示“探测到疑似坐标【分包未确认】”。这只能证明收到了疑似坐标文本。

**不能把空闲间隔当可靠消息边界。** 网络延迟可能把半条纬度先送来；不带分隔符的两条坐标也可能连在一起。本工具不会把这种候选记录提交给后台、回成功包或用于地图。即便探测模式看到换行，坐标仍一律标候选，避免混用两种规则。

### 第四步：使用远程入口

组合启动工具已经使用“原始 TCP 转发”，将公网入口转发到 **127.0.0.1:18765**。不需要将接收程序改成监听全部网卡，也不需要关闭 Mac 防火墙。

公网地址、端口由服务实际分配，以本次启动输出为准。本轮没有安装或购买服务。普通网页 HTTPS 隧道不能直接当作本协议的 TCP 地址。

工程师需要拿到：公网域名/IP、公网端口、TCP 或 TLS、分包规则、回包约定、测试时段。认证资料另走安全渠道。

**只有你电脑到穿透平台这一段加密，并不等于设备到平台这一段也加密。** 传输真实位置前，必须确认设备侧支持 TLS 或经双方验证的安全网络方案，并落实认证。无认证的旧固件先只用合成坐标，限制测试时段；不要把临时裸 TCP 测试口当生产服务。

## 3. 发给硬件工程师的话

> 接收程序和临时 TCP 穿透已准备好。我会把本次启动生成的公网地址、端口和到期时间一起发你，先用合成坐标测试。
>
> 请确认三件事：每条数据末尾有没有 \n 或 \r\n？坐标系是 WGS84 还是 GCJ-02？服务端需要回什么内容，还是不用回？如果还没有固定分包协议，建议每条后面加换行，避免多条数据连在一起。
>
> 当前程序默认不回包。我们先用测试点位跑通上传，验证服务器确实收到，再接小程序地图。后续正式定位还需要设备唯一编号、实际采集时间及认证方式。

收到答复后，再确认支持 TLS、测试认证、定位来源、精度、无效定位怎么表示、断线重连和能否下发立即定位指令。

## 4. 支持的格式与参数

### 推荐双方确认的首轮格式

```text
120.0001_30.0001\r\n
```

上面是合成样例；`\r\n` 表示实际回车、换行字节 `0D 0A`，不是发送反斜杠字符。`\n`（`0A`）也支持。

| 项目 | 当前行为 |
|---|---|
| 编码 | ASCII 数字文本 / UTF-8；负号、小数点、下划线；不支持 HEX 二进制坐标协议 |
| 坐标 | 前经度、后纬度；按十进制度解析；拒绝越界、NaN、附加乱码及 0_0；不猜测 NMEA 度分格式 |
| 坐标系 | 默认 UNKNOWN；人工确认后可标 WGS84 / GCJ02，本工具不进行地图转换 |
| 时间 | receivedAt 只表示电脑收到时间；measuredAt 为 null，不能假装是设备采集时间 |
| 设备身份 | C1/C2 是临时连接编号，不是设备 ID；不能用于绑定孩子 |
| 注册信息 | 可识别包含 imei/iccid 的换行 JSON，只提示收到注册信息，不保留号码、不据此认证 |
| 心跳 | 可识别 `PING` 换行；其他固件心跳需提供原文再适配，不默认回应 |
| 回包 | 默认无；显式开启时只对严格模式下格式通过的坐标回复 `OK\r\n`；须先与硬件确认 |
| 无换行 | 严格模式等待，半包 15 秒未完成会断开；探测模式只能产生待确认候选 |
| 重复点位 | 每次接收都计数，不当作孩子移动；无设备消息号/采集时间，无法做正式去重或乱序判定 |
| 清理 | 默认每连接只保留最新一条，60 秒或断开后清除；此 60 秒仅为本机展示保留期，不是正式定位有效期 |

常用命令：

```sh
# 改本地端口（穿透转发端口也要对应调整）
npm run device:tcp -- --port 18766

# 仅当硬件确认坐标系以及回包格式后使用
npm run device:tcp -- --coordinate-system WGS84 --ack ok

# 查看所有参数
npm run device:tcp -- --help
```

### 可选认证与 TLS

配置清单见 `tools/mini-location-tcp/.env.example`，程序**不自动读取**此文件。真实口令通过进程环境设置，不能写入 README、截图、命令参数、公开聊天或仓库。

- 设置 `MINI_TCP_TOKEN` 后，客户端必须先发送 `AUTH <测试口令>\n`，10 秒内完成；未认证数据直接拒绝。口令至少 24 字符。
- 这是可选的本工具测试握手，**不是厂家已经实现的协议**。现有固件不支持时不要擅自开启；先由双方确认安全测试方案。
- 同时设置 `MINI_TCP_TLS_CERT` 和 `MINI_TCP_TLS_KEY` 的文件路径，接收端启用 TLS 1.2+。设备必须支持 TLS 并验证相应证书，不是给裸 TCP 换一个域名就能加密。
- 证书和私钥可放 `tools/mini-location-tcp/private/`（已忽略），不提交 Git。环境文件也已被仓库忽略。
- TLS 本机模拟器通过 `--tls` 开启，并要求 `MINI_TCP_TLS_CA`、`MINI_TCP_TLS_SERVERNAME`；不支持跳过证书验证。
- 共享测试口令不是正式设备身份体系。正式接入还需每设备凭据、可信绑定及撤销机制。

## 5. 本机兼容测试

接收程序保持运行，发送器可依次执行：

```sh
npm run device:tcp:send -- --scenario normal
npm run device:tcp:send -- --scenario split
npm run device:tcp:send -- --scenario sticky
npm run device:tcp:send -- --scenario invalid
npm run device:tcp:send -- --scenario registration
npm run device:tcp:send -- --scenario no-newline
```

| 场景 | 应看到什么 |
|---|---|
| normal | 两条完整坐标；不是实际设备数据 |
| split | 模拟一次消息分四次传输，最终只收到一条完整坐标 |
| sticky | 两条消息一次发送，仍解析出两条 |
| invalid | 非法格式、越界和 0_0 被拒绝，不覆盖最近格式正确记录 |
| registration | 先提示注册信息，再解析坐标；不会据此认定设备已认证 |
| no-newline | 严格模式提示等换行；探测模式显示候选，不回成功包 |

自动测试：

```sh
npm run device:tcp:test
npm run verify
```

新增测试覆盖：格式、注册、分包、超长消息、真实 TCP socket、ACK、认证、限流、超时、清理、端口释放、默认日志脱敏和真实 TLS socket。TLS 测试使用系统 `openssl` 生成临时测试证书；本机 Node.js 22.22.2 已可运行，无第三方 npm 依赖。

## 6. 如何判断双方上传测试完成

- 硬件连接的是新分配的公网入口，不是 127.0.0.1，也不是测试工具连接列表里的来源端口。
- 本机出现连接记录，并连续收到格式正确的上报；工程师端发送条数与本机接收计数一致。
- 使用双方同意的测试点位核对经纬度；电脑接收时间和设备采集时间分开理解。
- 测试断网、恢复、重复坐标、定位失败；异常不冒充成功。
- 回包要求已确认，设备不会因未收到预期回包而反复重连。
- 停止测试时 Ctrl+C 关闭接收程序，并关闭穿透连接；不保留无人值守入口。

**本机收到数据 ≠ 小程序真实定位完成。** 后续还要补设备编号、坐标系、采集时间、定位有效性、鉴权和可信绑定，再接 CloudBase 及守护地图。现有截图数据还不足以生成正式后台要求的定位事件，不会自动伪造这些字段。
