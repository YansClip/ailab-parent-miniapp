# 硬件位置收包测试（2026-10-12）

## 本轮确认与边界

用户已确认：工程师知晓并同意上传自己的位置，由用户在小程序查看；不使用儿童位置。**取消 A/B 两点限制**。硬件继续发送现有注册 JSON 和固定 17 字节经纬度，正常范围内的坐标均可接收；本机自动测试的虚构样例由软件侧生成，不要求工程师改成测试点。

这一批是**本地代码与验证**，未部署云端，未修改云端授权/数据库/费用配置，也没有生成公网地址。此前业务服务和数据库的连通不等于硬件 TCP 入口已经存在。临时本机穿透仍不算“电脑关闭后也能接收”。

## 数据路径

```text
硬件：原注册 JSON + fixed17 坐标
  ↓ 受保护的 TCP 接入（落点和传输保护尚待确认）
测试接收器：注册信息映射到指定测试设备，不打印原始报文
  ↓ HTTPS + 独立签名
独立测试接收接口 → 私有 MySQL 的单设备最新收包记录
  ↑ 现有私有业务后台核验微信身份、绑定和定位权限
手机：体验设置 → 硬件定位测试 → 查看经纬度/收包时间
```

业务后台仍只允许微信可信网关访问。**不要为了接硬件而打开业务后台的公网访问或相信客户端自行传入的 OpenID。**测试接收服务不挂载身份、家庭、通话或数据库管理接口。

## 硬件无需改变的部分

- 保留现有注册 JSON（`imei` 或 `iccid`）与 `DDD.dddd_DD.ddddd`，不需要增加 A/B 标记、HMAC、HTTP、额外 AUTH 报文。签名由软件侧接收器完成。
- 支持 TCP 分包、粘包、可选 CR/LF；不新增 ACK。
- 注册号由后台私有配置映射到测试设备别名及绑定版本。它**不是秘密，也不能证明硬件身份**；不能把它当正式设备认证。
- 当前 fixed17 本身只能表达这一固定宽度的正数格式；不擅自解释负数、NMEA、经纬度交换或任意 JSON 坐标。后续如格式变化需双方确认。
- 仍做必要合法性校验：经纬度范围、非 0/0、完整报文、指定注册设备、限速、测试有效期。不是“只允许某两个位置”。

## 手机测试页说明

入口：我的 → 体验设置 → **打开硬件定位测试页**。

1. 主动登录并同意隐私规则，点击“读取本人云端设备”。这一步只读取，不创建或修改授权。
2. 选择指定测试设备，点击“开始检查收包”。后台必须同时满足指定查看者白名单、有效家庭/设备绑定、`viewDevice` 与 `locateDevice` 权限；前端按钮不能授予这些权限。
3. 每 5 秒读取一次；正常显示经度、纬度、**服务器收到于**及坐标系。坐标系未知时只显示数值，不放到地图上猜测位置。
4. 30 秒没有新收包、确认断连、查询失败、主动停止或离开页面后清除显示。原报文没有 GPS 采集时间，故不标记“实时 GPS”，也不提供轨迹。
5. 未部署时提示“尚未部署接口”；未开启/测试结束时提示相应状态；无权限不返回坐标、不补示例点。当前手机版本不会因 GitHub 推送自动更新。

主界面的 `mode: demo`、已有正式定位接口、独立模拟定位台、旧 TCP 联调台和音视频开关都保持原行为。收包测试不会将旧报文冒充正式 GNSS 数据。

## 软件侧配置（部署前再填，不是现在让用户复制）

业务后台/独立测试接收接口使用：

| 参数 | 含义 |
| --- | --- |
| `TEST_LOCATION_ENABLED` | 显式开启，默认 false |
| `TEST_LOCATION_TESTS_JSON` | 指定 `familyId/childId/deviceId/bindingVersion` 的数组 |
| `TEST_LOCATION_READERS_JSON` | 只填获准查看者的 OpenID 数组；不代替已有定位授权 |
| `TEST_LOCATION_EXPIRES_AT` | 带时区的测试截止时间 |
| `TEST_LOCATION_RELAY_KEYS_JSON` | 接收服务专用签名密钥与可上报设备范围；不用于微信鉴权 |

独立测试接收服务用 `SERVICE_ROLE=test-location-ingress`，HTTP 路径 `/api/test-location/report`；公网代理必须 HTTPS。业务服务仍为 `SERVICE_ROLE=business`。`LOCATION_PROVIDER` 不为这次诊断自动切换为 `push`，通话也不启用。

TCP 测试接收器命令：`npm run device:location:receipt:relay`。启动前须通过**本机私有环境变量**提供：

- `TEST_LOCATION_TCP_HOST` / `TEST_LOCATION_TCP_PORT`：默认 `127.0.0.1:18769`，不占用旧台端口。
- `TEST_LOCATION_TCP_DEVICES_JSON`：每项 `deviceId`、`bindingVersion`、`registrationField`（imei/iccid）、`registrationValue`、`coordinateSystem`（UNKNOWN/WGS84/GCJ02）。登记号不要提交到 GitHub。
- `TEST_LOCATION_EXPIRES_AT`：不超过 24 小时的明确截止时间。
- `TEST_LOCATION_INGRESS_URL`、`TEST_LOCATION_RELAY_KEY_ID`、`TEST_LOCATION_RELAY_SECRET`：签名 HTTPS 转发配置；仅本机自动测试允许 loopback HTTP。
- 非本机监听额外要求 `TEST_LOCATION_TLS_CERT_FILE` / `TEST_LOCATION_TLS_KEY_FILE` 和 `TEST_LOCATION_TCP_SOURCE_IPS_JSON`。本代码**不会自动创建明文公网入口或隧道**。来源 IP 限制和注册号匹配不等于硬件密码认证。

所有配置缺失默认失败，不回退到演示结果。旧固定格式兼容不代表板子的 TLS 能力已确认；如工程师当前模块不支持 TLS，需要先选定受保护的接入方案，不能直接把未加密的公网 TCP 当作正式上线方案。

## 存储与隐私

沿用通用记录表，新增逻辑集合 `mini_test_location_channels`，不是新数据库/轨迹表。每台设备仅覆盖最新记录；保留收包时间、诊断状态和去重摘要，不记录原始注册信息、原始报文、轨迹、声音或画面。后台读接口和日志都不输出密钥。

有效期到达立即停止返回坐标，运行中清理器每 10 秒尝试清空当前点。服务缩容到 0、数据库故障可能推迟物理清理；数据库备份/日志也可能保留历史存储版本。**不承诺 30 秒内所有存储及备份物理删除**。测试结束需检查清理状态及数据库备份保留策略；真实儿童试运行前还需完成适用的隐私、安全与正式定位验收。

## 本地验证与下一步

自动化命令：`npm run device:location:receipt:test`、`npm run verify`。覆盖任意合法样例坐标、签名路径隔离、TCP 分包/粘包、读写、绑定/权限撤回、去重/乱序、过期、断连和前端迟到响应。隔离 MySQL 测试仅使用可丢弃的本机 MySQL 8.0，不代表重新验收现有云端 MySQL 5.7。

本批验证结果：全量 **336 项测试通过**，48 页静态检查 0 错误、0 警告；另有 **8 项隔离 MySQL 集成测试通过**，包括仅 SELECT/INSERT/UPDATE/DELETE 权限的本机应用账号读写，以及建表操作被拒绝。修正了重复执行数据库测试受上一轮测试记录影响的问题，已重跑通过。临时容器与自动生成的数据卷已随容器退出清理，不影响其他本机容器或云端数据库。未进行新页面的微信真机视觉验收、真实硬件上传、云端部署或云端 MySQL 5.7 重验。

部署前信息：用户暂时无法确认硬件联网模块及 TLS 支持情况，稍后补充；在此之前不选择或开通新的 TCP 云资源。

下一步顺序：

1. 软件侧给出实际可部署的 TCP 接入落点、传输保护方式及预计费用，先由用户确认；不默认已拥有可开放 TCP 端口的云主机。
2. 工程师只需确认现有注册字段、上报间隔、坐标系、联网模块及 TLS 支持情况；无需为 A/B 修改固件。真实注册号私下传递。
3. 用户确认后再部署接收链路和后台，核对私有业务入口隔离、绑定版本、仅本人定位权限、测试截止时间。公网数据库始终不开。
4. 软件侧用合成数据验证云端链路，再给工程师最终地址/端口/所需传输配置；工程师上报自己的位置，用户在手机测试页核对。
5. 断网/恢复、过期、撤权测试通过，并确认电脑关闭仍能上报，才记为云端硬件收包联调通过。最后补 GPS 采集时间、坐标系/精度和正式设备认证，进入地图实时定位验收。

本批不触及音视频服务器、通话授权或移动网络硬件能力结论。
