# 微信官方硬件音视频重启计划（待用户确认）

日期：2026-10-13。依据：[官方资料阅读记录（57 篇）](WECHAT-VOIP-OFFICIAL-READING-2026-10-13.md)、[当前开发进度](PROJECT-STATUS-2026-10-13.md)。

状态：文档学习和进度核查已完成；本计划尚待确认，未据此改功能代码、部署、开放权限或购买资源。确认开发计划也不自动授权付费、生产部署或小程序发布。

## 1. 这次保留什么、重做什么

**保留**：微信云托管、MySQL、可信微信身份和业务权限基础、可复用的页面/状态逻辑、定位及模拟工具、GitHub 历史。

**重新开发/核验**：仅以微信官方文档为依据的小程序通话接入、票据和分方向授权、微信原生事件处理、官方云对云媒体进程、设备端 RTOS SDK 与音画数据通道。

**退出当前方案**：探鸽/TiRTC、此前考虑的腾讯云 RTC/其他音视频产品路线。旧代码和文档暂时保留为历史资产，不作为新功能依据、不重新启用。微信官方 SDK 由腾讯提供不意味着本项目又改回腾讯云 RTC；微信云托管/MySQL 明确保留。

已确认的产品目标：同一台随身设备在家中 Wi-Fi 和离家移动网络下，定位、语音、视频均可用；家长与设备都能主动呼叫，双向声音和双向画面；不保存录音录像、不提供历史轨迹。先使用成人测试者，不使用儿童数据。

用户于 2026-10-13 补充确认：**只做家长与设备双向音视频通话，摄像头用于通话，不增加独立“查看设备摄像头”功能**。因此本计划不接入独立 `camera-device` 查看组件，不做不发起通话直接查看画面或静默监控。此项范围已确认，具体开发计划仍待确认。

## 2. 用白话说明最终架构

现有业务后台相当于“核对谁能联系哪台设备、记录这次通话的状态”；数据库保存必要业务关系，不用来传声音或存视频。

新增的官方媒体程序相当于“传声音和画面的中转员”。P4 走官方 RTOS 云对云路径时，这个程序和设备到它的通道仍要我们与硬件工程师实现，不能由小程序按钮或 MySQL 自动生成。

```text
身份、绑定和呼叫许可：
手机小程序 ↔ 现有云托管业务后台 ↔ 私有 MySQL
                   ↕
           微信可信事件 / 通话控制
                   ↕
              媒体会话管理程序

真实声音与画面（目标）：
P4 设备 ↔ 我们的云端媒体程序（官方 SDK）↔ 微信音视频网络 ↔ 手机官方插件
```

正式目标不经过用户电脑。电脑只用于开发、编译和观察日志。初期本机验证不能被当成这个最终目标已经完成。

### 是否要买新服务器

现在不能直接回答“一定要”或“一定不要”。已有业务服务器保留；媒体程序需要额外运行能力，但软件组件增加不等于必然购买另一台云主机。

先检查官方 SDK 与当前承载环境：x86_64、glibc ≥ 2.28、libcurl ≥ 7.84.0、每进程一通会话、多进程/IPC、所需出入站协议/端口、持续连接、休眠与回收、磁盘/状态生命周期、流量和并发预算。Mac 上跑模拟请求或 CloudRun 返回 200 都不能代替这些验证。

如果现有云托管能满足并实测通过，可在合适的隔离服务中承载；否则再提出专用运行资源、费用与迁移方案，由用户确认。不得为了媒体接入把现有可信身份业务接口或数据库直接开放公网；也不把一个新的 HTTPS 地址误称为完整音视频服务器。

## 3. 先后顺序与每阶段的过关证据

### A. 已完成：进度、官方资料、差异清单

- 全量进度分类，不把 demo 算成云端业务完成。
- 归档 57 篇文档、表格、示例代码及配图已读，正文/代码与原网页校验通过。
- 识别旧供应商依赖、两个呼叫方向、原生回调、媒体进程和 P4 下行解码的缺口。
- 更新记忆和历史文档标记；保持功能代码、部署和权限不变。

### B. 确认计划后：固定官方开发基线

由我们核对官方插件/平台配置；硬件工程师核对样机和 RTOS 适配。先取得本次实际使用的官方设备端、服务端 SDK 包与 example，完整读版本说明、头文件、示例和许可，记录版本/校验值，明确手机插件版本组合。页面里出现的旧 TiRTC SDK 2.3.0 不再是本次版本基线。

必须得到的少量实证：

1. 账号侧：主体与类目、硬件能力、VoIP 测试权限、设备 ModelID、官方插件可用性；正式版审核/许可证/费用另标状态。
2. 设备侧：实际鱼鹰 P4+C5 板卡/系统/固件，官方 RTOS SDK 能初始化、设备注册和保存必要身份数据；不能烧启明镜像来代替验证。
3. 音频侧：本地麦克风采集、扬声器播放和回声控制可用；给出格式、采样率、声道、帧长和实测结果。
4. 视频侧提前排雷：H.264 上行编码、下行解码/渲染/旋转的可行性证据。旧“下行 JPEG”不代表已具备微信下行视频能力；若需云端转码，先评估实现、延迟和资源，不默认已支持。
5. 云端侧：选定 SDK 的官方示例在兼容环境初始化；明确设备↔云信令/媒体传输及认证方案。具体协议按 SDK/固件能力选定，不凭文档空白处自创“微信规定的协议”。

B 阶段先做文档/本地原型和兼容性测试；遇到未包含的官方资料补读，缺失则说明，不靠猜测解锁下一阶段。部署及费用需要时再单独确认。

### C. 第一个实机闭环：手机呼叫设备，先双向语音

只用 1 台实体设备、1 个获准的成人微信账号、测试家庭，先在稳定 Wi-Fi 下测试。

- 小程序：接入官方插件和真实通话页；从后台获得匹配当前绑定的目标/呼叫意图；`callDevice({isCloud:true, roomType:'voice', ...})`；处理冷/热启动、重复导航、取消/超时与指定房间挂断。
- 业务与事件：官方短期票据能力；可信 `iot_voip_notify` 入口；核验微信事件、调用者、SN/ModelID、绑定/权限/有效期；去重；正确 ACK。不能相信可篡改 payload 或手填 OpenID。
- 云端：先把来电送到设备；设备接听后调用 `wx_cloudvoip_session_cloud_call_join`；收发音频，按每通话独立进程管理生命周期；拒接/忙线/挂断走对应官方接口。
- 硬件：响铃并显示来电，成人主动接听后开启采集/播放，接通后双向说话，任一方挂断后停止采集/传输。

过关：双方实际听到对方；连续通话、重复呼叫与任一方挂断均可复现。建议记录 5 分钟通话和 10 次重复呼叫，作为本项目待确认的测试样本量，不是微信官方达标线。创建 roomId、服务器响应或进入 TALKING 都不是音质验收。

### D. 补齐反向呼叫：设备呼叫家长

- 先由家长主动执行 `wx.requestDeviceVoIP`，核验授权/设置状态；此步骤是设备呼入提醒的前提，不错误阻挡 C 阶段手机主动呼出。
- 设备 `wx_cloudvoip_client_call`；微信可信推送到我们后台；服务器按该方向调用 `wx_cloudvoip_session_join`；手机按官方插件流程接听。
- 验证前台、后台、锁屏/冷启动，及授权关闭、拒接、忙线、无人接听、取消和通知关闭的明确反馈。

过关：两个方向均能真实呼叫、说话与结束；权限失效和通知限制不会被伪装成成功。平台/系统限制如实记录，不承诺所有手机状态必响铃。

### E. 加入双向视频

先使用验证过的小分辨率、帧率和带宽组合，再逐步提升；同时保留双向语音。

- 设备上行：摄像头采集、H.264 编码、SPS/PPS/关键帧、发送时机与缓冲。
- 设备下行：手机视频的编码、实际分辨率及变化、旋转/镜像、解码/渲染；必要的 SDK 订阅参数与小程序编码参数匹配。
- 手机端：区分 `setUIConfig` 的显示比例与编码宽高比，按 `contain/fill` 官方图例和实机确认；不能把屏幕比例、视频宽高、编码旋转写成同一个参数。

过关：手机看到设备画面、设备看到手机画面；方向/镜像正确，声音仍双向；拒接/结束后两端停止媒体。只显示设备单向画面不能算双向视频完成。

### F. 移动网络、异常与正式业务整合

设备离开家中 Wi-Fi 后，在实际蜂窝模块/SIM 上测试两个方向的语音和视频；分别测试手机 Wi-Fi/移动网络、设备网络切换/重连、弱网、通话中来系统电话、进程崩溃和迟到回调。

同时补齐身份/家庭/设备管理真实接口、许可审核和上线安全，核验解绑/换绑/撤权、另一成年账号隔离、资源清理、敏感日志和成本。摄像头仅在已接听的视频通话中工作；不把独立查看画面加入本阶段。

最终以电脑关闭后仍能进行实际云端通话、目标手机/设备组合可复现为准。阶段 C～F 的测试部署、权限及资源使用应有明确范围和回退方式。

## 6. 新开发的防错规则

1. 每个外部接口对应官方原文或实际 SDK 头文件/例程；未确认的内容写成假设/待验证，不写成微信规定。
2. 不将 Android/Linux 接法混进 RTOS；不将普通设备订阅消息当来电提醒；不将旧供应商授权查询当官方能力。
3. 不将业务接口成功、roomId、插件事件、SDK 状态自动等同于双方音画正常。
4. 业务权限校验、微信提醒授权、设备身份认证三层分别实现；前端按钮和环境变量确认标记本身不能建立外部可信来源。
5. 设备与云传输、微信回调、数据库各自核验保护；不把“工程师同意测试”理解为可以忽略安全。
6. 不录音、不录像、不上传调试音画到公开仓库；日志只保留排障必要的脱敏状态，保留时间在部署前明确。
7. 测试先本地合成，再批准的云端测试，再成人实机；故障不降级成模拟成功。
8. 每批相关修改检查、回归、提交/推送；部署与发布仍另行确认。旧逻辑删除/数据库迁移有单独回退计划。

## 7. 计划确认后第一步做什么

不是立刻让用户填写一堆服务器地址，也不是立刻让硬件上传视频。

先由我们整理当前平台权限证据及所选官方 SDK 材料，向硬件工程师交付“一台鱼鹰 P4、官方 RTOS SDK、Wi-Fi 双向语音”的最小任务；并验证云端 SDK 的运行环境。需要用户登录或确认费用时再给一个明确的操作步骤。缺哪个具体材料就核对哪个，不重复询问已经明确的 Wi-Fi/移动网络、双向呼叫、不录音录像需求。
