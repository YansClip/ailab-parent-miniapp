## 4. 定位：接收过硬件，不等于手机已看到云端硬件位置

已分别具备以下部分，但不能把分段成功拼成已经完整成功：

```text
硬件 → 本机 TCP 接收                         历史成功
本机模拟上报 → 接口 → 测试存储 → 测试页面       本地成功
手机 → 既有云业务后台 → MySQL → 虚构设备列表    历史成功
硬件 → 常驻云端入口 → MySQL → 手机真实点位      尚未验收
```

现有新测试页只显示最新收包、服务器收到时间和可确定的坐标系；原报文缺少 GPS 时间就不冒称实时 GPS，坐标系未知就不猜地图位置。不要求硬件限制到 A/B 点；只使用已同意的成年工程师位置，不使用儿童数据。

最终去掉电脑有两类实施方向，尚未选定并部署：硬件适配认证 HTTPS 直接上报云入口，或部署能持续接 TCP/TLS 的云端接收器再转给业务后台。前者需要固件改动，后者需要验证接收服务承载资源；不能承诺现有 CloudRun 的 HTTP 端口直接接裸 TCP，也不能未经评估就要求购买服务器。

下一次定位任务应先确认最终入口和传输保护，核实所提供 ML307C 资料与实际固件能力是否一致，再安排单设备、限时、可撤销测试部署，最终以“关闭开发电脑仍能上报并在手机看到新点位”验收。本次不执行这些部署。
