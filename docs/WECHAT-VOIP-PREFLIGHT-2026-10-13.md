## 3. 设备端 v4：有候选，仍需真实固件验证

### 库与编译环境

- 两套 v4 ESP32 库各含 7 个 ELF 对象，静态检查为 32 位小端 RISC-V；编译器版本字符串与目录一致。
- 对象标记为 RVC、单精度浮点 ABI；ISA 属性还包含 `D` 等扩展。ESP32-P4 的具体 ISA、工具链目标参数与库属性必须匹配；应检查 `-march`、`-mabi`、实际链接代码并实机运行。不能只看目录含 ESP32 就宣称已兼容，也不能仅凭属性标记断言一定无法运行。
- 不因版本号较新就选择 GCC 14 库。先取工程师的 `idf.py --version`、`riscv32-esp-elf-gcc --version`，以及当前能编译的工程或 `sdkconfig`、组件依赖和实际编译参数。
- 包中有 ESP32 OS/网络适配源文件，但没有一套可直接烧录鱼鹰 P4 的完整 ESP-IDF 工程；不得直接执行其他板卡的旧镜像。

### 文档与真实接口不完全一致

| 证据 | 项目处理 |
|---|---|
| v4 实际 `wx_init` 接收 `wxvoip_network_https_impl_t`，网络回调为 `post_with_resp`；README 前部仍混有旧网络接口写法 | 使用同一版本的真实头文件，不照搬 v3 的 connect/send/recv 适配 |
| v4 README 写有 `wx_cloudvoip_client_join`，静态库也导出该符号，但所附客户端头文件没有该声明 | 不手写猜测声明；若要用该入口，先取得官方匹配头文件。当前手机云代理路线按官方 034 + 服务端 `cloud_call_join` 规划，不额外叠加此调用 |
| 设备例程默认正式环境、视频模式 | 首轮采用平台实际允许的开发/体验环境及纯语音模式，不能原样发起正式视频呼叫 |
| 轻量设备 SDK 负责注册/呼叫等控制 | 采集、播放、AEC、编解码、设备↔自有云媒体通道仍需我们与硬件工程师实现 |

### FreeRTOS 示例不能当成成品适配层

`device/v4/demo/src/freertos/esp32_os_impl.c`：NVS 打开错误处理、命名空间长度、保存后的 `nvs_commit`、二进制日志、随机数/时钟与网络信息适配均须核查。示例写入后没有显式 commit，不能据此承诺断电/重启后设备身份仍正确保存。命名空间和提交要求见 [ESP-IDF NVS 文档](https://docs.espressif.com/projects/esp-idf/en/stable/esp32p4/api-reference/storage/nvs_flash.html)；文档 stable 版本不等于实际固件版本。

`esp32_tls_impl.c`：示例手动拼装/解析 HTTP，包含固定缓冲区、长度/状态/分块响应、超时与错误路径清理等适配风险。接入时优先评估实际 ESP-IDF 的 HTTPS 客户端，补齐证书验证、请求/响应大小上限、有限超时和失败清理；不能为了跑通关闭 TLS 校验。

以上是对所附适配示例的观察，不是对闭源 SDK 内部实现已完成漏洞审计的声明。

## 4. 服务端 D5100032：不是现有 Node 后台的一个配置开关

本包 9 个共享库静态识别为 **Linux ELF64 x86-64**。保留官方归档 022 的兼容条件：glibc ≥ 2.28、libcurl ≥ 7.84.0；一个 SDK 进程同时处理一通会话。多通话需要工作进程与 IPC 管理。静态依赖检查不能替代实际动态加载和连通验证。

本机 Mac 是 Darwin arm64，现有本机 Docker 服务端也是 Linux arm64，均不是该包的原生目标；可能的 amd64 模拟环境尚未启动或验证。当前云托管实例的 CPU 架构、依赖、持续连接、回收策略和资源费用本轮未复核。

因此：保留 CloudRun/MySQL 业务层；媒体组件隔离评估，不提前断言必须另买云服务器，也不承诺现有服务一定可直接承载。任何云端部署或新增费用先确认。

### 两个方向的入口已经能在本包找到

- 手机 → 设备：按官方云代理流程通知设备；设备明确接听后，服务端 `wx_cloudvoip_session_cloud_call_join`。
- 设备 → 手机：设备 `wx_cloudvoip_client_call`，可信官方事件到达后台后，服务端 `wx_cloudvoip_session_join`。
- 对应 session/listener 挂断、销毁及 operation 结果处理必须完整实现。`wx_operation_wait` 的无限等待不能直接用于业务请求；超时、取消与销毁按该 SDK 的生命周期处理。

这仅确认接口存在及其适用流程；尚未获得有效通话票据或完成真实入会。

### 会影响本项目的示例行为

| SDK 文件 / 行为 | 接入前必须做的处理 |
|---|---|
| `example/audio_impl.c` 会写 `play.pcm`，`video_impl.c` 会写 `video.h264` | 不使用其录制逻辑；实现受控内存缓冲和实时转发，通话结束清理。不能拿原样演示程序测试真实音画 |
| 主例程打印 token、session_key、payload 等；示例运行参数也可能暴露凭证 | 日志脱敏，不用真实秘密做命令行演示；票据安全传递、短期持有，不写仓库 |
| 音频播放路径在未收到视频时提前返回 | 改为独立音频生命周期，验证纯语音无视频也能双向传声 |
| 上行示例读取音频/视频文件 | 替换为实际设备通道；样例文件回放不是设备麦克风/摄像头链路 |

“不录音录像”不等于禁止一切 SDK 状态目录：必要认证/状态持久化与媒体内容必须分开，明确最小保存内容、权限和清理期限。

## 5. 鱼鹰 P4：硬件资料支持什么，不支持推断什么

依据用户提供的《ESP32-P4-Module 使用指南 2026.09.10（含原理图）》6 页及《ESP32P4 模组基础底板 V1.3》原理图。读取与视觉核查使用用户下载目录中的同名副本；原文件不复制进公开仓库。

- 指南包含 P4+C5 / P4+C6 差异及 V1.3/V1.4/V1.5 板卡变化；指南末页是 V1.5 原理图，另一文件是 V1.3。**必须确定实物版本，不能混用引脚、复位电平和旧固件配置。**
- 资料标注 P4、PSRAM/Flash、摄像头/屏幕接口，电路含 ES8311 音频 codec、功放与麦克风，具备开展采集/播放适配的基础；实际 SKU、驱动初始化、全双工与回声消除仍待实测。
- P4 支持 H.264 硬件编码。乐鑫官方 ESP-H264 还提供 TinyH264 软件解码路径，见 [ESP-H264 组件说明](https://docs.espressif.com/projects/esp-adf/en/latest/basic-components/video-codec/esp-h264.html)。因此不能先断言 P4 不能解码、必须换板或云端转码；也不能宣称软件解码已经达到双向视频性能。须实测码流 profile、分辨率、帧率、屏幕旋转和音频并行负载。
- 现存其他型号/旧 TiRTC 固件工程不是鱼鹰实物的可信构建基线；其中的 ESP-IDF 版本不能直接归给本设备。
- ML307C 的 AT/TCP 定位资料不能证明音视频联网通道已完成。首轮稳定 Wi-Fi；蜂窝 IP 通路、重连与流量在后续阶段独立验证。
