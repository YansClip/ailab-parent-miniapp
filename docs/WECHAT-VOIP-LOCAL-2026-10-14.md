## 本地怎么试

1. 微信开发者工具打开本仓库，重新编译。进入「我的 → 体验设置 → 打开官方通话本地演练」；也可自定义编译页面 `pages/my/official-voip-test`。
2. 默认「手机 → 设备 / 语音」：发起 → 通知送达 → 设备主动接听 → 模拟媒体加入 → 挂断。全程无声音、画面或真实呼叫。
3. 重新发起，分别试拒接、忙线、主叫取消；等待接听时点「时间前进 31 秒」应结束为超时。
4. 切换「设备 → 手机」：提醒未授权时应阻止；打开**模拟**提醒开关后重复流程。该开关不改变微信授权。
5. 通话过程中关闭模拟通话权限/绑定/在线条件，应结束；再恢复条件不能复活旧通话。离开页面后再进入应为空。
6. 视频选项只验证业务阶段，不能作为双向视频已实现的证据。

```bash
npm run device:voip:official:test
npm run verify
npm run device:voip:sdk-check -- --sdk-dir /absolute/path/to/official-server-sdk
```

SDK 目录应包含 `include/wmpf/` 和 `lib/libwxcloudvoip_server.so`。工具不下载 SDK、不运行 demo、不联网、不输出原始 SDK 日志。默认退出成功仅代表头文件检查成功；`--strict` 在未完成真实就绪验证时返回失败。

实际本机检查结果：头文件通过（编译前显式包含标准 `time.h`）；库为 ELF64 Linux x86-64，本机为 macOS arm64，不能据此声称可原生运行。原生 Linux 环境/依赖/网络实测需下一阶段确认，**本结论不是“必须新买服务器”**。首先评估现有资源能否满足持续媒体进程与网络需求，再决定是否需新增费用。

## 我方与硬件之间的接口边界（待共同确认，不是微信官方协议）

以下是下一阶段自有设备通道需要承载的业务含义，不要求工程师现在按这些名字改报文。正式编码、分包、鉴权、重传及编解码参数须以真实 SDK 和工程能力共同确定。

| 业务方向 | 最小职责 | 校验与处理 |
|---|---|---|
| 云 → 设备：来电通知 | 提供关联会话、语音/视频类型、受控联系人显示信息 | 可信微信回调验签解密后核对本人/绑定/通话意图；不能仅凭 payload 或设备自报权限放行 |
| 设备 → 云：主动接听/拒接 | 设备显示来电，由使用者明确操作 | 校验设备通道身份、同一会话、同一绑定版本、有效期限；先接听后云端 join，禁止自动/静默接听 |
| 设备 → 微信 / 云：设备主动呼出 | 按 RTOS `client_call` 发起，家长接听 | 先验证业务联系人/权限及提醒准备；收到对应可信回调后走设备发起的 session_join |
| 任一端 → 对端：取消/挂断 | 区分未接听取消与已加入会话挂断 | 手机呼设备尚未建立 session 时按文档 listener_hangup；已有 session 则 session_hangup，并清理 session/设备音画资源；不能把“已发指令”当已停止 |
| 设备 ↔ 媒体进程 | 麦克风上行、扬声器下行；后续加摄像头上行/屏幕下行 | 根据 SDK stream 参数和实际编解码能力确认格式、采样率、帧时长、分辨率、关键帧与时间戳；有界内存队列，不保存媒体，不打印票据 |
| 断网/重连/撤权 | 停止采集播放，结束旧会话并清理缓存 | 迟到/重复/串会话消息不能恢复旧通话；重连不得自动重拨或静默恢复摄像头 |

本地演练采用 30 秒等待接听/加入、5 分钟总时长，仅是可测试的项目策略，不声称是微信平台限额。当前媒体占位状态始终 `mediaVerified:false / captureAllowed:false`。

服务端 SDK 单进程只支持一个会话实例，未来应采用单通话工作进程与明确资源回收。现有 Node API 继续承担业务权限，不直接冒充原生媒体服务。微信票据、server_token、session_key、明文 OpenID 不进入设备调试日志或公开仓库；官方示例中的媒体落盘、凭证日志不能照搬。

## 还需要提供什么（可分批，不要求一次交齐）

**硬件工程师先补最小构建资料：**

1. 实际 P4 板/底板版本（清晰照片或丝印），C5 已确认，不再重复问型号。
2. `idf.py --version` 与 `riscv32-esp-elf-gcc --version` 完整输出。
3. 当前能编译运行的最小工程，或先给 `CMakeLists.txt`、组件依赖、`sdkconfig.defaults` 与构建日志；移除 Wi-Fi 密码、设备密钥。包含 C5 配套固件/通信驱动版本及 P4↔C5 连接配置。
4. 在现有板上先验麦克风采集、扬声器播放、设备端接听/挂断操作与 Wi-Fi 稳定联网；视频阶段再验摄像头编码、屏幕解码播放。不以“能拍照/JPEG 显示”代替双向视频能力。

**用户这边只需补平台进度：**设备登记是否提交/审核通过、取得的 ModelID 和音视频能力/插件授权状态截图（遮住密钥、二维码及个人信息）。登记表已填不等于许可已开通；普通设备消息能力也不等于 VoIP 许可。若尚未提交，继续沿用登记草稿，不臆造生产厂商或产品类型。

**我方下一阶段顺序：**收到工具链后选设备库并做最小编译；平台条件齐后实现并验证官方安全回调/票据/插件事件适配；评估现有运行环境，部署或新增费用先确认；成人单设备 Wi-Fi 下手机呼出双向语音 → 设备反向呼叫 → 双向视频 → 移动网络。期间不使用真实儿童音视频或位置。
