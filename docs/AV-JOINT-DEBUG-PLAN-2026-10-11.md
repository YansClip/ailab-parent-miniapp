# 音视频通话联调方案（2026-10-11）

目标：先跑通「我们的小程序呼叫一台测试设备」，先双向声音，再双向画面，最后验收拒接、超时、断网、挂断。只用成人测试人员和虚构家庭；不使用真实儿童数据。

## 现状与路线

业务云托管 `ailab-device-gateway`、数据库及本人微信身份已通过手机检查；虚构测试设备 A 的绑定版本为 3，通话权限仍关闭。小程序已有通话适配、授权和状态代码，但真实媒体、供应商接口、微信型号许可尚未联合验证。**业务后台连通不等于通话服务就绪。**

建议沿用 TiRTC + 微信硬件通话插件，优先请硬件方协调探鸽提供现有测试服务；先用供应商演示小程序验证鱼鹰板，再接入我们的 AppID。若没有测试服务，先明确服务实现/托管责任和费用，再决定部署，不能把现有业务服务地址当成 TiRTC 地址。

链路分工：我们的小程序负责身份、授权和呼叫；通话业务服务负责微信原生回调、媒体凭证和设备通知；TiRTC 平台负责媒体连接/转码；设备负责采集、播放和接听。当前自建业务服务只是其中一部分。[供应商服务端接入说明](https://docs.tange.ai/products/wxvoip/en/guides/app-server.html)

## 双方准备

| 负责方 | 必须准备/确认 |
|---|---|
| 我们（开发） | 可信微信身份、测试家庭/设备绑定、授权流程、官方插件适配、呼叫状态与错误处理；待实际接口明确后补适配和可信回执接入 |
| 你（微信账号管理员） | 本 AppID 的硬件音视频许可、设备 ModelID、插件授权及固定版本；测试时在手机上主动授权麦克风/摄像头和设备通话 |
| 硬件工程师 | 鱼鹰 P4+C5 专用固件；麦克风→编码→上行、下行→解码→扬声器；AEC；摄像头和屏幕；接听/拒接/挂断；媒体参数和脱敏串口日志 |
| 硬件方协调供应商/通话后端负责人 | 测试服务是否已有；设备注册与凭证签发；微信原生回调、设备长连接通知、TiRTC 凭证/转码；供我们对接的用户接口、授权与通话状态样例 |

**硬件风险：**提供的 WT9932P4C61-TINY 1.0.2 发布资料明确说明音频底板未接、采集/播放/AEC 关闭且未验收；这不能证明鱼鹰板也没声音，但必须单独验证，不能从摄像头 H.264 编码成功推断双向语音可用。启明 P4+C61 镜像不能直接烧鱼鹰 P4+C5。[对应版本发布页](https://github.com/tangeai/tirtc-device-qiming/releases/tag/esp32-p4-wt9932p4c61-tiny-device-app-v1.0.2)

## 联调顺序与过关标准

1. **确认服务和样机**：硬件方给出适配固件及现有测试服务；用其演示小程序与鱼鹰板完成声音/画面验证。演示小程序 OpenID 不能替代我们 AppID 下的 OpenID。
2. **核对本项目参数**：确认 AppID、ModelID、设备 SN、测试账号归属、媒体能力；用真实脱敏请求/响应核对现有适配。微信许可通过并不等于设备已上线。
3. **接上呼叫和回执**：明确谁收微信原生回调、谁下发设备通知、谁向我们的后台提供可信状态。必须补独立可信接入方案；当前云托管代码硬性关闭通话回执，不是仅改环境变量即可。不得开放现有身份业务接口让外部伪造微信身份。
4. **先测语音**：我们的小程序发起→设备响铃→成人主动接听→双方说话均可听到→任一方挂断后设备不再采集/发送。建议持续 5 分钟，重复 10 次呼叫，记录单向无声、回声、断音与时延；这是待执行标准，不是已通过结果。
5. **再测视频及异常**：手机见设备画面、设备见手机画面，声音仍双向；检查旋转/镜像；测试拒接、无人接听、离线、断网、重复事件、撤销授权和旧绑定。两端退出且媒体停止才算结束；收到房间号或“接口成功”不算接通。

本轮不部署、不改云端权限、不启用真实呼叫、不购买资源。参数及回执方案明确后，再单独安排测试部署和真实设备授权。最终媒体应走云端/供应商平台，电脑只用于开发与查看串口；目前还不能宣布真机联调已不需要本机临时服务。

## 可以直接发给硬件工程师

> 我们业务后台和数据库已连通，小程序已备好身份、设备授权和通话适配，但还没接真实 TiRTC 通话服务。先联调“小程序呼叫设备”，先双向声音再双向视频。请确认鱼鹰 P4+C5 的适配固件和麦克风/扬声器/AEC 是否可用；提供现有测试服务或协调探鸽提供。请分别说明设备上线/注册、消息通知、媒体连接及小程序用户接口的地址与负责人，确认设备 SN/密钥由谁签发、微信 ModelID 和插件版本。请给实际媒体能力上报、来电/接听/结束的脱敏样例，并确认接听后怎么挂断、谁接收微信原生回调。我们需要基于真实样例对齐接口，不直接烧启明镜像。凭证请通过安全渠道提供，不放群聊、文档或截图。

## 我们已先完成的本地准备

- `npm run device:voip:check`：列出本地配置、可信回执硬阻断及外部待确认事项；不读取云端凭证。加 `-- --json` 可获取结构化结果。
- `npm run device:voip:rehearse`：用内存虚构家庭/设备，经实际通话状态和 HMAC 验签代码，演练接听、视频就绪、挂断、签名、重复、乱序、绑定和权限等 12 项；不联网、不写云数据库。
- `npm run device:voip:rehearse -- --example`：输出一份虚构的**我们内部标准化回执**，不是微信原生或 TiRTC 原生协议。接口对齐详见 [回执对齐说明](AV-RELAY-CONTRACT-2026-10-11.md)。
